本文档用于统一描述郑育星小程序当前产品范围、业务规则、页面结构、数据状态、接口约束、隐私要求、验收标准和上线差距。

本文档既是产品需求说明，也是当前实现基线。开发、UI 和测试应以本文档中的“目标规则”和“当前实现状态”共同判断任务范围，不能把开发环境的模拟能力当作正式上线能力。

| 状态 | 含义 |

### 1.4 重要事实说明

1. 当前项目不是纯前端项目，已包含可运行的 Node.js 后端和后台管理网页。
2. 当前本地后端默认运行在 `http://127.0.0.1:3000`。
3. 当前正式环境 API 地址尚未配置，体验版与正式版不能直接连接本地地址。
4. 当前微信登录和微信手机号授权已预留真实微信接口，并保留开发环境 mock。
5. 当前联系方式付费解锁在开发环境使用 mock 支付，尚未接入真实微信支付。
6. 当前数据主要保存在本地 JSON 文件，不是生产级数据库。
7. 当前后台网页覆盖老师审核、老师管理、家长管理、前端配置和日志等基础模块，但订单、投诉、评价、家长需求和价格规则的后台网页闭环不完整。
8. 当前自动化测试覆盖 38 个用例；仍需微信开发者工具编译、真机、网络、支付和审核链路验收。

## 2. 项目背景

### 2.1 用户问题

郑州本地家长寻找大学生辅导老师时，常通过熟人介绍、社区群、兼职群和零散信息渠道完成。现有方式主要存在以下问题：

1. 老师身份和在校信息难核实。
2. 信息分散，科目、年级、区域和时间难统一筛选。
3. 联系方式默认公开，容易造成隐私泄露和骚扰。
4. 价格不透明，双方沟通成本高。
5. 预约、上课、评价和问题反馈缺少留痕。
6. 家长不知道如何快速找到适合孩子年级和科目的老师。
7. 大学生老师难以稳定获取真实、明确的辅导需求。

### 2.2 产品定位

郑育星定位为郑州本地大学生老师信息展示、家长需求展示、预约撮合和服务留痕平台。

平台连接两类核心用户：

1. 家长用户：浏览和筛选老师、发布辅导需求、解锁老师联系方式、发起预约、管理订单、评价和反馈问题。
2. 老师用户：提交入驻资料、等待平台审核、浏览家长需求、解锁家长联系方式、处理预约订单和查看评价。

平台不是培训机构，不直接提供教学服务，不承诺具体学习结果。

### 2.3 产品价值

#### 对家长

1. 按科目、年级、区域、学校和价格筛选老师。
2. 查看经过平台审核的老师基础资料。
3. 通过预约和订单记录管理服务过程。
4. 在需要时付费解锁老师完整资料和联系方式。
5. 通过评价和投诉反馈降低选择风险。

#### 对老师

1. 提交在校大学生资料并获得平台展示机会。
2. 按能力、科目、年级、区域和时间接收适合的需求。
3. 浏览家长公开需求并按规则解锁联系方式。
4. 管理接单状态、预约进度和历史评价。

#### 对平台

1. 通过老师审核和信息管理建立基础信任。
2. 通过付费解锁联系方式形成第一版商业闭环。
3. 通过预约、评价、投诉和联系记录形成可追溯服务记录。
4. 通过后台配置降低前端固定内容的修改成本。

### 2.4 产品原则

1. 可信优先：老师资料需审核，敏感材料不在用户端公开。
2. 隐私优先：联系方式默认隐藏，必须满足授权和解锁条件后返回。
3. 双端分流：家长与老师拥有不同首页、资料、权限和操作路径。
4. 服务留痕：预约、订单状态、评价、投诉和解锁记录由服务端保存。
5. 结果克制：不得出现保分、保过、快速提分、名校必上等承诺。
6. 开发与生产隔离：mock 登录、mock 手机号和 mock 支付只能用于开发环境。
7. 后端为业务真相：支付成功、审核通过、解锁权益和订单状态不能仅由前端决定。

### 3.1 第一版范围

1. 游客公开浏览。
2. 微信登录与微信手机号授权。

7. 老师列表、筛选、详情、认证标签和评价摘要。
8. 家长需求发布、列表、筛选和详情。
9. 家长解锁老师联系方式。
10. 审核通过老师解锁家长需求联系方式。

8. 自动退款和复杂财务对账。
9. 复杂多级管理员权限体系。

## 4. 用户角色与权限

### 4.1 游客

游客是未登录用户。

允许操作：

1. 查看首页公开内容。
2. 查看老师列表和公开筛选结果。
3. 查看老师详情中的公开字段。
4. 查看平台说明、用户协议和隐私政策。

禁止操作：

1. 查看完整联系方式。
2. 付费解锁信息。
3. 创建预约。
4. 发布家长需求。
5. 提交老师入驻资料。
6. 查看订单、解锁记录和联系记录。
7. 提交评价和投诉。

### 4.2 家长

家长是完成家长身份和家长资料的普通用户。

核心权限：

1. 浏览、筛选和查看老师。
2. 解锁老师联系方式。
3. 创建预约并管理自己的订单。
4. 发布和查看自己的家长需求。
5. 查看自己的解锁记录和联系记录。
6. 对已完成订单评价。
7. 对关联订单提交投诉。
8. 申请新增老师身份。

关键限制：

1. 创建预约、公开发布需求、解锁信息和投诉前需绑定手机号。
2. 只能操作自己的资料、需求、订单、评价和投诉。
3. 不能预约自己的老师身份。

### 4.3 老师

老师是选择老师身份并提交入驻资料的用户。

核心权限：

1. 提交和编辑老师资料。
2. 查看审核状态与驳回原因。
3. 审核通过后切换可接单或暂停接单。
4. 审核通过后浏览家长公开需求。
5. 审核通过后解锁家长需求联系方式。
6. 查看和处理分配给自己的预约订单。
7. 查看自己的评价。
8. 查看自己的解锁记录和联系记录。

关键限制：

1. 老师资料提交前必须绑定手机号。
2. 审核未通过时不能进入老师公开列表。
3. 审核未通过时不能接收新预约或解锁家长联系方式。
4. 被封禁老师不能展示、接单或购买解锁。

### 4.4 管理员

管理员使用独立后台账号、管理员 Token 和后台接口。

核心权限：

1. 登录后台并查看数据看板。
2. 查看老师申请和认证材料。
3. 审核通过或驳回老师申请。
4. 禁用、恢复和推荐老师。
5. 查看脱敏家长基础信息并冻结、解冻账号。
6. 编辑公开前端配置。
7. 查看解锁记录和操作日志。
8. 通过旧后台接口查看订单、投诉和评价并处理部分状态。

隐私限制：

1. 后台列表不得展示完整手机号。
2. 不展示微信 openid。
3. 不展示孩子姓名、学校、班级和家庭详细地址。
4. 老师学生证仅允许审核详情查看。
5. 敏感操作需记录管理员、目标、原因和时间。

## 5. 核心状态模型

### 5.1 用户账号状态 `accountStatus`

| 状态 | 页面含义 | 业务限制 |
| --- | --- | --- |
| `normal` | 正常 | 可按角色使用功能 |
| `frozen` | 冻结 | 不允许发布、预约、购买或提交投诉 |
| `banned` | 封禁 | 不允许进入受限业务，不进入展示池 |

### 5.2 资料状态 `profileStatus`

| 状态 | 含义 | 登录后处理 |
| --- | --- | --- |
| `pending_role` | 未选择身份 | 进入身份选择页 |
| `pending_profile` | 已选择身份但资料未完成 | 进入对应资料填写页 |
| `completed` | 当前身份资料已完成 | 进入当前身份首页或目标业务 |

### 5.3 当前身份与拥有身份

`currentRole` 可选：

- `parent`
- `teacher`
- 空值

`roles` 是用户已拥有身份的数组，可为：

- `[]`
- `["parent"]`
- `["teacher"]`
- `["parent", "teacher"]`

系统必须根据 `currentRole` 展示当前首页和业务权限，不能因为用户提交过老师资料就自动切换老师身份。

### 5.4 手机号状态

| 状态 | 含义 | 关键操作 |
| --- | --- | --- |
| `unbound` | 未绑定 | 可浏览；不能预约、公开需求、老师入驻、解锁或投诉 |
| `bound` | 已绑定 | 满足其他条件后可执行关键操作 |

### 5.5 老师审核状态 `teacherAuditStatus`

| 状态 | 含义 | 展示和操作 |
| --- | --- | --- |
| `not_submitted` | 未提交资料 | 不展示，不可接单 |
| `pending` | 待审核 | 不展示，不可接单 |
| `approved` | 审核通过 | 接单状态可用时可展示、预约和解锁需求 |
| `rejected` | 审核驳回 | 不展示，显示驳回原因，可修改后重提 |
| `rechecking` | 复审中 | 暂停展示或按平台规则处理，不可新增接单 |
| `banned` | 已封禁 | 不展示，不可接单和解锁 |

### 5.6 老师接单状态 `orderStatus`

| 状态 | 含义 |
| --- | --- |
| `available` | 可接收新预约 |
| `paused` | 暂停接收新预约 |

只有审核状态为 `approved` 的老师可以修改接单状态。

### 5.7 订单状态

| 状态 | 中文 | 允许的主要下一步 |
| --- | --- | --- |
| `pending_teacher` | 待老师确认 | 老师接受或拒绝；家长取消 |
| `pending_class` | 待上课 | 老师开始上课 |
| `in_class` | 上课中 | 老师完成授课 |
| `pending_parent_confirm` | 待家长确认 | 家长确认完成 |
| `completed` | 已完成 | 家长评价 |
| `canceled` | 已取消 | 终态 |
| `rejected` | 已拒绝 | 终态 |
| `complaint` | 投诉中 | 后台处理后关闭或按原状态处理 |
| `closed` | 已关闭 | 终态 |

### 5.8 投诉状态

| 状态 | 中文 |
| --- | --- |
| `pending` | 待处理 |
| `processing` | 处理中 |
| `resolved` | 已处理 |

## 7. 登录与账户体系

### 7.1 登录方式

当前代码包含两套普通用户登录方式：

1. 微信登录：正式产品的主要登录方式。
2. 账号密码注册与登录：已实现页面和后端能力，主要用于本地测试和后续备用登录。

管理员使用独立后台账号密码登录，不能使用普通用户 Token 访问后台接口。

### 7.2 微信登录流程

1. 用户阅读并同意用户协议和隐私政策。
2. 小程序调用 `wx.login` 获取临时 `code`。
3. 前端调用 `POST /api/auth/wechat-login`。
4. 后端在正式配置下调用微信 `code2Session` 获取 openid。
5. openid 不存在时创建新用户，资料状态为 `pending_role`。
6. openid 已存在时读取原用户身份和资料状态。
7. 后端返回用户 Token 和脱敏用户信息，不返回 openid。
8. 前端按资料状态和当前身份分流。

当前状态：

- 真实 `code2Session` 代码路径已实现。
- 开发环境可使用稳定 mock openid。
- 正式上线仍需配置真实 AppID、AppSecret、HTTPS API 域名并真机验证。

### 7.3 账号密码注册

注册字段：

1. 手机号。
2. 密码。
3. 确认密码。
4. 短信验证码。
5. 用户协议和隐私政策同意。

校验规则：

1. 手机号必须为中国大陆手机号格式。
2. 密码至少 8 位，并同时包含字母和数字。
3. 两次密码必须一致。
4. 手机号不能重复注册。
5. 密码使用 bcrypt 强哈希存储，不保存明文。
6. 注册成功后资料状态为 `pending_role`。

当前状态：

- 页面、接口、bcrypt 哈希和重复注册校验已实现。
- 开发环境验证码为固定测试验证码。
- 生产环境未接入短信服务，因此正式注册暂不能闭环。

### 7.4 账号密码登录

1. 用户使用手机号或账号和密码登录。
2. 错误统一提示“手机号或密码错误”，不暴露账号是否存在。
3. 连续 5 次失败后临时锁定 30 分钟。
4. 冻结或封禁用户不能进入受限业务。
5. 登录成功后按资料状态和当前身份分流。
6. 历史 SHA-256 密码成功登录后自动升级为 bcrypt。

### 7.5 Token 与退出登录

1. 普通用户 Token 和管理员 Token 类型隔离。
2. 用户退出登录调用服务端吊销当前 Token。
3. 新登录产生的新 Token不受旧 Token 吊销影响。
4. Token 过期或被吊销时接口返回 `401`。
5. 前端收到 `401` 后清除本地登录态，并显示重新登录入口。
6. 生产环境必须配置高强度 Token 密钥，禁止使用默认回退密钥。

### 7.6 登录后分流

| 条件 | 目标 |
| --- | --- |
| 未登录 | 游客首页 |
| `profileStatus = pending_role` | 身份选择页 |
| `pending_profile + parent` | 家长资料页 |
| `pending_profile + teacher` | 老师入驻页 |
| `completed + parent` | 家长版首页 |
| `completed + teacher` | 老师版首页或老师工作台 |

如果登录由预约、需求发布、老师入驻或解锁触发，应先完成身份与资料前置条件，再返回原目标业务。

## 15. 联系方式付费解锁

### 15.1 商业规则

| --- | --- | --- | --- |

### 15.2 解锁前置条件

家长解锁老师：

5. 老师审核通过。

### 15.3 解锁流程

1. 用户进入目标详情。
2. 服务端返回公开字段和当前解锁状态。
3. 未解锁时展示锁定模块。
4. 用户点击解锁，弹出金额、隐私和退款提示。
5. 服务端再次检查身份、目标状态和重复购买。
6. 未解锁时创建支付订单。
7. 正式环境调用微信支付。
8. 微信支付回调由后端验签并幂等处理。
9. 支付成功后服务端创建解锁记录。
10. 前端重新请求目标详情。
11. 服务端确认权益后返回完整字段。

同一购买用户、目标类型和目标 ID 只能存在一个有效解锁权益。已解锁用户再次点击时直接返回详情，不创建新支付订单。

2. 当前账号正常。
3. 资料状态已完成。
4. 手机号已绑定。
5. 目标老师审核通过且可接单。
6. 不能预约自己的老师身份。
7. 预约科目必须属于老师可授课科目。

当前待完善：

1. 后端需显式校验下单用户必须具备家长身份。
2. 年级与老师可授课年级的匹配需服务端校验。
3. 服务区域需与老师可服务区域匹配。
4. 时间范围、结束时间和重复时段冲突需校验。

### 17.3 订单状态流

```text
待老师确认
  -> 老师接受 -> 待上课
  -> 老师开始 -> 上课中
  -> 老师完成 -> 待家长确认
  -> 家长确认 -> 已完成

待老师确认
  -> 家长取消 -> 已取消
  -> 老师拒绝 -> 已拒绝

非终态订单
  -> 发起投诉 -> 投诉中
  -> 后台处理 -> 已关闭或按处理结果记录
```

### 17.4 操作矩阵

| 订单状态 | 家长操作 | 老师操作 |
| --- | --- | --- |
| 待老师确认 | 取消、投诉 | 接受、拒绝、投诉 |
| 待上课 | 投诉 | 开始上课、投诉 |
| 上课中 | 投诉 | 完成授课、投诉 |
| 待家长确认 | 确认完成、投诉 | 查看 |
| 已完成 | 评价、查看 | 查看 |
| 已取消/已拒绝/已关闭 | 查看 | 查看 |

### 17.5 地址与联系方式保护

1. 家长始终可查看自己订单填写的地址。
2. 老师在接受订单前不能查看详细地址、联系人和联系电话。
3. 老师接受订单后才能查看。
4. 已拒绝订单不展示详细地址。
5. 管理员仅在处理必要业务时查看，且应记录敏感访问。

当前已知问题：订单视图中的家长基础对象可能在老师接受前返回家长手机号，需在正式上线前修复并增加隐私测试。

## 23. 后台管理系统

### 23.1 管理员认证

1. 管理员账号或手机号和密码登录。
2. 密码使用 bcrypt 哈希。
3. 连续 5 次失败锁定 30 分钟。
4. 登录成功返回管理员 Token。
5. 普通用户 Token 访问后台接口返回 `403`。
6. 管理员退出后吊销当前 Token。
7. 支持一次性 ticket 换取管理员 Token 的后端接口。

当前本地存在默认管理员账号，仅用于开发。生产上线前必须关闭默认账号或强制修改密码。

## 27. 隐私与安全

### 27.1 敏感数据

敏感数据包括：

1. 手机号。
2. 微信号。
3. 家庭详细地址。
4. 学生证照片。
5. openid。
6. 密码哈希。
7. 管理员 Token。
8. 微信 AppSecret 和支付证书。

### 27.2 返回规则

1. 未解锁接口不返回联系方式字段，而不是返回后由前端隐藏。
2. 普通列表只返回脱敏手机号或不返回手机号。
3. 学生证仅管理员审核详情可访问。
4. openid 不返回普通前端。
5. 密码哈希永不返回。
6. 老师接受订单前不返回家长详细地址和联系电话。

### 27.3 存储规则

1. 密码使用 bcrypt。
2. 生产联系方式应加密存储。
3. 密钥通过环境变量管理。
4. 正式数据不得保存在代码仓库。
5. 上传文件需要私有存储或受控访问，不能长期依赖公开静态目录。

### 27.4 防绕过

老师介绍和家长需求文本应检测：

1. 连续 11 位手机号。
2. 微信号引导词和疑似微信 ID。
3. 二维码。
4. 精确门牌地址。

前后端都要校验；前端提示不能替代后端拦截。

### 27.5 合规说明

1. 正式上线前需复核隐私政策、用户协议、联系方式展示授权和退款说明。
2. 联系方式授权应单独记录授权文案版本、授权时间和用户。
3. 微信支付、手机号授权和用户隐私需按微信公众平台最新要求配置。
4. 本文档不是法律意见，正式运营需由合规负责人审核。

## 29. 错误处理

| HTTP 状态 | 前端处理 |
| --- | --- |
| `400` | 展示具体参数或业务提示 |
| `401` | 清理失效登录态，提示重新登录 |
| `403` | 展示无权限、身份不符或审核未通过原因 |
| `404` | 展示内容不存在或已下架 |
| `409` | 展示状态冲突或重复操作 |
| `429` | 提示操作频繁，稍后重试 |
| `500` | 提示服务器异常并保留重试入口 |
| 请求失败 | 提示网络异常，不把所有业务错误归类为网络异常 |

| 生产闭环 | 正式服务、正式配置、真实设备、权限、安全和数据全部可用 |

## 37. 文档结论

当前项目已经具备一个较完整的本地 MVP：小程序、后端、后台管理网页、用户身份、老师审核、双向信息展示、开发环境付费解锁、预约订单、评价和投诉均有实际代码基础。

当前主要问题不是缺少页面，而是正式上线闭环不足。真实微信支付、正式数据库、正式域名与密钥、上传存储、后台完整管理、快速匹配和订单隐私修复是下一阶段重点。

任何上线宣传、收入测试或真实用户试用前，必须先完成 P0 阻断项，并使用微信开发者工具和真机对登录、手机号、支付、解锁、预约、地址保护、评价和投诉进行完整回归。
