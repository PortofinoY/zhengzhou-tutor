# 郑育星上门家教小程序开发规范

## 1. 目标

本规范用于约束小程序、后端、数据库和后台管理端的后续开发。原则是：范围清晰、接口稳定、数据可信、开发与生产隔离、每一步可验证。

## 2. 目录与职责

- `miniprogram/pages/`：页面展示和用户交互，不直接保存业务真相。
- `miniprogram/utils/`：请求、鉴权、环境和可复用业务辅助函数。
- `server/src/api.js`：接口路由、权限校验和业务流程编排。
- `server/src/validators.js`：后端输入校验，前端校验不能替代这里的校验。
- `server/src/store.js`：当前本地数据访问层；迁移数据库后由 Repository 层替代。
- `database/schema.sql`：正式数据库结构基线，字段调整必须同步更新。
- `server/public/admin/`：后台管理网页，不复用普通用户 Token。
- `server/test/`：接口、状态流转、权限和前端纯函数测试。

页面不能直接操作数据库，前端不能自行决定支付成功、解锁成功、审核通过或订单状态。

## 3. 开发流程

每个任务按以下顺序执行：

1. 明确本次范围、涉及文件和验收结果。
2. 先读取现有实现，禁止凭文件名猜逻辑。
3. 为新增行为补测试，并确认测试在实现前失败。
4. 只修改当前任务需要的文件，不顺手重构其他模块。
5. 完成后运行完整测试、语法检查和 `git diff --check`。
6. 汇报修改文件、验证结果、尚未完成项和生产限制。

工作区存在用户未提交代码时必须保留，不得重置、覆盖或回滚无关修改。

## 4. 环境规范

小程序环境以微信 `envVersion` 为唯一判断来源：

| 环境 | `envVersion` | API 地址 | Mock | 测试入口 |
| --- | --- | --- | --- | --- |
| 开发版 | `develop` | 本地 Node 服务 | 允许 | 显示 |
| 体验版 | `trial` | 正式 HTTPS 测试域名 | 禁止 | 隐藏 |
| 正式版 | `release` | 正式 HTTPS 域名 | 禁止 | 隐藏 |

规则：

- 体验版和正式版不得访问 `localhost`、`127.0.0.1` 或局域网地址。
- Mock 微信登录、Mock 手机号、固定短信验证码和 Mock 支付只能在开发环境使用。
- 前端隐藏 Mock 按钮不是安全措施，后端必须再次拒绝 Mock 接口。
- 正式 API 地址未配置时直接报错，不允许静默降级到本地服务。
- 密钥只能通过服务端环境变量配置，不写入小程序代码或 Git。

## 5. 接口规范

- 小程序接口统一使用 `/api`，后台接口统一使用 `/admin-api`。
- 返回格式统一为 `{ code, message, data }`。
- `401` 表示未登录或登录过期，`403` 表示无权限，`404` 表示资源或接口不存在，`409` 表示状态冲突，`429` 表示频率限制。
- 页面不得混用不同返回层级；请求封装统一解析 `data`。
- 接口金额、角色、审核状态、支付状态和资源归属必须由服务端计算或校验。
- 新接口必须包含成功、参数错误、未登录、无权限和重复操作测试。

## 6. 登录与权限规范

- 微信 Token、普通用户 Token、管理员 Token 不得混用。
- 新用户必须经过身份选择和资料完善后才能进入受限业务。
- 密码统一使用 bcrypt 强哈希，默认成本因子为 12；不得记录或返回明文密码。
- 历史 SHA-256 密码仅用于兼容校验，用户首次成功登录后必须自动迁移为 bcrypt。
- 连续登录失败需要限流或临时锁定。
- 退出登录在正式版本中应支持服务端 Token 吊销。
- 用户只能操作属于自己的资料、需求、订单、评价、投诉和解锁记录。

## 7. 数据与隐私规范

- 手机号、微信号、详细地址、学生证等敏感数据默认不返回。
- 联系方式必须同时满足用户授权、购买权益有效、目标状态有效后才能返回。
- 联系方式字段正式上线前必须加密存储，日志和后台列表只展示脱敏值。
- 用户简介和需求内容必须检测手机号、微信号和二维码等绕过付费的信息。
- 数据表新增字段时同步更新 schema、迁移脚本、Store/Repository、接口和测试。
- 支付、解锁、审核和订单流转必须具备幂等约束。

## 8. 前端规范

- 页面只维护展示状态，不将支付成功、审核通过等关键状态仅保存在本地。
- 所有页面必须提供加载、空数据、错误和禁用状态。
- 跳转前确认目标页面已登记在 `app.json`。
- 非 Tab 页使用 `navigateTo/redirectTo`，Tab 页使用 `switchTab`。
- 图片上传必须先获得永久 URL，再提交业务表单；不得保存临时文件路径。
- 测试入口、演示账号、Mock 文案必须由环境配置控制。

## 9. 后端规范

- 路由层不信任前端输入，所有字段和权限在服务端校验。
- 状态流转采用允许列表，不允许任意写入状态字段。
- 生产环境禁止默认密钥、默认管理员密码和开放 Mock 接口。
- 敏感操作记录操作人、对象、操作前后状态、原因和时间。
- 错误返回不能泄露密码哈希、openid、数据库路径或调用堆栈。

## 10. 测试与验收

每个功能至少覆盖：

- 正常流程。
- 未登录和角色错误。
- 参数边界。
- 重复提交。
- 状态不允许。
- 隐私字段不泄露。

提交前必须通过：

```bash
npm test
git diff --check
```

小程序页面修改还需要在微信开发者工具完成编译，并人工验证返回、空状态和异常提示。

## 11. Git 规范

- 一个提交只包含一个可说明的功能或修复。
- 不提交密码、AppSecret、支付证书、真实手机号或生产数据库。
- 不提交临时图片、开发者工具缓存和无关格式化结果。
- 提交信息使用 `feat:`、`fix:`、`test:`、`docs:`、`refactor:` 前缀。

## 12. 完成定义

功能只有同时满足以下条件才算完成：

1. 前后端行为与产品规则一致。
2. 页面入口和返回路径可用。
3. 后端权限和参数校验完整。
4. 数据可以正确持久化。
5. 自动化测试通过。
6. 微信开发者工具可以编译。
7. 开发和生产环境行为明确隔离。
8. 文档记录真实限制，不用 Mock 冒充生产能力。
