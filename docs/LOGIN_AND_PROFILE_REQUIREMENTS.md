# 郑州大学生家教小程序登录与资料填写产品文档

| 项目 | 内容 |
| --- | --- |
| 文档名称 | 郑州大学生家教小程序登录与资料填写产品文档 |
| 产品版本 | 第一版 |
| 适用范围 | 微信登录、身份选择、手机号授权、家长资料、老师资料、登录后分流 |
| 目标用户 | 家长用户、大学生家教老师 |
| 登录方式 | 微信登录 + 微信授权手机号 |
| 文档用途 | 产品、开发、UI、测试对齐 |

## 1. 文档目标与范围

### 1.1 功能目标

用户首次使用小程序时，通过微信登录建立账户。系统根据用户是否已选择身份、是否完成资料，自动进入身份选择页、家长资料页、老师资料页或对应身份首页。

本流程需要实现以下目标：

1. 降低新用户登录成本。
2. 让家长和老师填写不同的必要信息。
3. 在关键操作前完成手机号授权。
4. 让老师资料进入审核，未通过审核的老师不能进入展示池或解锁家长需求。
5. 让老用户再次登录时，不重复选择身份，不重复填写已完成资料。

### 1.2 本文档覆盖范围

- 微信登录。
- 新老用户判断。
- 身份选择。
- 微信手机号授权。
- 家长资料填写、保存和编辑。
- 老师资料填写、保存、审核状态和编辑。
- 登录成功后的页面跳转。
- 登录、资料和手机号授权的权限校验。

### 1.3 本文档不覆盖范围

- 普通用户账号密码注册与登录。
- 手机号短信验证码登录。
- 管理员后台账号密码登录。
- 微信支付、付费解锁、预约订单、评价和问题反馈的完整业务规则。

付费解锁、家长需求发布和价格规则见《郑州大学生家教小程序第一版产品文档》。本文件仅描述其依赖的登录、身份和资料前置条件。

## 2. 用户角色、状态与数据关系

### 2.1 用户角色

| 角色 | 说明 | 首次需完成的资料 |
| --- | --- | --- |
| 游客 | 未登录用户 | 无 |
| 家长 | 为孩子寻找家教老师的用户 | 家长基础资料 |
| 老师 | 申请成为平台大学生家教老师的用户 | 老师入驻资料与学生证材料 |

同一用户可以同时拥有家长和老师身份。当前使用身份由 `currentRole` 决定，系统不得根据是否提交过老师资料自动切换身份。

### 2.2 用户状态定义

| 字段 | 可选值 | 定义 | 使用规则 |
| --- | --- | --- | --- |
| `loginStatus` | `logged_out`、`logged_in` | 是否完成微信登录 | 未登录只能浏览公开内容 |
| `phoneBindStatus` | `unbound`、`bound` | 是否完成微信手机号授权 | 关键动作前必须为 `bound` |
| `profileStatus` | `pending_role`、`pending_profile`、`completed` | 身份和资料完成情况 | 决定登录后跳转 |
| `currentRole` | `parent`、`teacher`、空 | 当前使用身份 | 决定首页和业务权限 |
| `roles` | `[]`、`[parent]`、`[teacher]`、`[parent, teacher]` | 用户已经拥有的身份集合 | 用于身份切换和申请新增身份 |
| `accountStatus` | `normal`、`frozen`、`banned` | 账号状态 | 非 `normal` 用户不能进入受限业务 |
| `teacherAuditStatus` | `not_submitted`、`pending`、`approved`、`rejected`、`banned` | 老师资料审核状态 | 仅老师身份使用 |

### 2.3 状态流转

```text
微信新用户登录
  -> profileStatus = pending_role
  -> 选择家长或老师身份
  -> profileStatus = pending_profile
  -> 填写对应资料
  -> profileStatus = completed
  -> 进入当前身份首页

老师资料提交
  -> teacherAuditStatus = pending
  -> 后台审核通过 / 驳回
  -> approved / rejected
```

### 2.4 数据对象关系

| 数据对象 | 与用户关系 | 说明 |
| --- | --- | --- |
| `user` | 一条用户主记录 | 保存微信身份、手机号绑定状态、当前身份和资料状态 |
| `parent_profile` | 一个用户最多一条 | 保存家长基础匹配信息 |
| `teacher` | 一个用户最多一条 | 保存老师入驻、审核和展示信息 |
| `teacher_grade_price` | 一个老师多条 | 保存老师按年级单元设置的课时费 |

## 3. 微信登录

### 3.1 登录方式

普通用户登录方式仅为微信登录。小程序调用 `wx.login` 获取临时 `code`，将 `code` 发送给后端。后端使用微信服务获取并保存用户的 openid，然后返回用户 token 和基础用户状态。

小程序前端不得展示、缓存或打印 openid。普通用户不提供账号密码登录、账号密码注册、短信验证码登录和短信验证码服务。

### 3.2 登录页

#### 页面元素

1. 小程序名称：郑州大学生家教。
2. 平台说明：用于展示大学生家教信息、预约撮合和服务记录。
3. 用户协议勾选框。
4. 隐私政策勾选框或合并同意项。
5. 用户协议入口。
6. 隐私政策入口。
7. 微信登录按钮。

#### 交互规则

1. 用户未勾选协议和隐私政策时，微信登录按钮可点击，但点击后提示“请先阅读并同意用户协议和隐私政策”。
2. 用户点击微信登录后，按钮进入 loading 状态，防止重复点击。
3. 前端调用 `wx.login` 获取 code。
4. 前端调用微信登录接口。
5. 登录成功后，前端保存用户 token 和脱敏后的 `userInfo`。
6. 前端根据 `accountStatus`、`profileStatus`、`currentRole` 执行登录后跳转。
7. 登录失败后，退出 loading 状态，不清除已存在且仍有效的登录态。

### 3.3 微信登录接口

**接口：** `POST /api/auth/wechat-login`

**请求参数：**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `code` | 是 | `wx.login` 返回的临时 code |

**成功返回：**

```json
{
  "token": "userToken",
  "isNewUser": true,
  "userInfo": {
    "id": 1,
    "nickname": "微信用户",
    "avatar": "",
    "phone": "",
    "phoneBindStatus": "unbound",
    "currentRole": null,
    "roles": [],
    "profileStatus": "pending_role",
    "accountStatus": "normal"
  }
}
```

**后端处理规则：**

1. openid 不存在时创建 `user` 记录。
2. 新用户默认 `phoneBindStatus = unbound`。
3. 新用户默认 `currentRole = null`、`roles = []`、`profileStatus = pending_role`、`accountStatus = normal`。
4. openid 已存在时返回已有用户状态，不重置资料或身份。
5. `accountStatus = frozen` 时返回业务错误“账号暂时不可用，请联系客服”。
6. `accountStatus = banned` 时返回业务错误“账号已被限制，请联系客服”。
7. 生产环境必须通过真实微信服务校验 code；开发环境 mock 登录必须仅在 `dev` 或 `test` 环境启用。

### 3.4 登录后跳转规则

| 条件 | 跳转页面 | 说明 |
| --- | --- | --- |
| `profileStatus = pending_role` | 身份选择页 | 新用户或未完成身份选择的老用户 |
| `profileStatus = pending_profile` 且 `currentRole = parent` | 家长资料填写页 | 继续完成家长资料 |
| `profileStatus = pending_profile` 且 `currentRole = teacher` | 老师资料填写页 | 继续完成老师资料 |
| `profileStatus = completed` 且 `currentRole = parent` | 家长版首页 | 正常进入 |
| `profileStatus = completed` 且 `currentRole = teacher` | 老师版首页 | 显示对应审核状态 |
| `accountStatus != normal` | 停留登录页 | 显示账号状态提示，不进入首页 |

如果用户从预约、发布需求、老师入驻或解锁流程进入登录页，登录完成后应优先返回原目标流程；但若用户的身份或资料未完成，必须先完成身份选择和资料填写，再返回原目标流程。

## 4. 身份选择

### 4.1 进入条件

用户在以下场景进入身份选择页：

1. 微信新用户首次登录成功。
2. 老用户 `profileStatus = pending_role`。
3. 已拥有一种身份的用户在“我的”页面申请新增另一种身份。

### 4.2 页面内容

页面标题：请选择你的身份。

| 身份卡片 | 标题 | 说明 | 点击后跳转 |
| --- | --- | --- | --- |
| 家长身份卡片 | 我是家长 | 为孩子寻找合适的大学生家教老师 | 家长资料填写页 |
| 老师身份卡片 | 我是老师 | 提交资料认证，成为平台家教老师 | 老师资料填写页 |

### 4.3 选择规则

1. 用户必须选择一种身份后才能进入完整首页。
2. 选择家长时，后端将 `currentRole` 设置为 `parent`，将 `parent` 写入 `roles`，并将 `profileStatus` 设置为 `pending_profile`。
3. 选择老师时，后端将 `currentRole` 设置为 `teacher`，将 `teacher` 写入 `roles`，并将 `profileStatus` 设置为 `pending_profile`。
4. 用户已有该身份时，不重复写入 `roles`。
5. 用户申请新增身份时，不能覆盖已完成的另一种身份资料。
6. 身份切换只改变 `currentRole`，不删除已有的家长资料、老师资料或订单记录。

### 4.4 选择身份接口

**接口：** `POST /api/auth/select-role`

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `role` | 是 | 仅允许 `parent` 或 `teacher` |

**返回：** 最新 `userInfo`，至少包含 `currentRole`、`roles`、`profileStatus`。

后端必须从 token 获取当前用户 ID，不能接受前端传入的用户 ID。

## 5. 手机号授权

### 5.1 授权方式

手机号只通过微信手机号授权获取，不提供手动手机号输入和短信验证码流程。前端使用微信提供的手机号授权能力获取 `phoneCode`，后端换取手机号并绑定到当前登录用户。

### 5.2 授权触发场景

| 场景 | 是否必须授权 | 说明 |
| --- | --- | --- |
| 浏览首页、老师列表、老师详情公开信息 | 否 | 保持低门槛浏览 |
| 完成家长基础资料 | 否 | 允许先完善匹配资料 |
| 提交家长公开需求 | 是 | 用于后续付费解锁联系 |
| 家长预约老师 | 是 | 用于订单联系 |
| 家长解锁老师联系方式 | 是 | 购买前置条件 |
| 家长提交问题反馈 | 是 | 便于平台联系 |
| 提交老师入驻资料 | 是 | 审核与后续联系前置条件 |
| 老师解锁家长联系方式 | 是 | 购买前置条件 |
| 老师修改联系方式 | 是 | 重新确认当前手机号 |

### 5.3 手机号授权页

#### 页面元素

1. 当前操作说明，例如“为方便后续联系，请授权手机号”。
2. 授权手机号按钮。
3. 暂不授权按钮。
4. 隐私说明入口。

#### 交互规则

1. 点击授权手机号后，调用微信手机号授权能力。
2. 授权成功后，调用绑定手机号接口并刷新本地 `userInfo`。
3. 授权失败或用户拒绝时，提示“需要授权手机号后才可以继续完成该操作”。
4. 用户点击暂不授权时返回上一页或停留当前页，不得标记为已绑定。
5. 已绑定用户再次进入该页时，显示“手机号已绑定”，不重复调用授权。

### 5.4 绑定手机号接口

**接口：** `POST /api/auth/bind-phone`

**请求头：** `Authorization: Bearer userToken`

**请求参数：**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `phoneCode` | 是 | 微信手机号授权返回的 code |

**后端处理规则：**

1. 校验用户 token。
2. 校验 `phoneCode` 有效性。
3. 保存完整手机号，仅在后端受控场景使用。
4. 返回给小程序的手机号必须脱敏，例如 `138****8000`。
5. 手机号已绑定到当前用户时，直接返回成功和最新用户信息。
6. 手机号已绑定到其他用户时返回“该手机号已被其他账号绑定，请联系客服处理”。

## 6. 家长资料填写

### 6.1 进入条件

用户满足以下条件时进入家长资料页：

1. 已完成微信登录。
2. `currentRole = parent`。
3. `profileStatus = pending_profile`，或用户主动编辑已有家长资料。

### 6.2 页面目标

家长资料仅用于基础匹配和后续预约，不收集孩子的过度隐私信息。表单应按“基本匹配信息”和“可选补充信息”分组显示。

### 6.3 字段定义

| 字段 | 必填 | 规则 | 用途 |
| --- | --- | --- | --- |
| 家长称呼 `parentName` | 是 | 1 至 20 个字符，如“王妈妈”“李爸爸” | 订单与需求展示称呼 |
| 所在区域 `district` | 是 | 从郑州区域字典单选 | 匹配可上门老师 |
| 孩子年级 `childGrade` | 是 | 从年级字典单选 | 匹配老师能力和价格规则 |
| 辅导科目 `subjects` | 是 | 至少选择 1 项，可多选 | 匹配老师科目 |
| 期望上课时间 `availableTime` | 否 | 可多选 | 提高匹配效率 |
| 学习情况 `studySituation` | 否 | 最多 300 字 | 帮助老师理解需求 |
| 对老师要求 `teacherRequirement` | 否 | 最多 300 字 | 帮助筛选老师 |

家长资料页不得收集：孩子真实姓名、孩子学校、孩子班级、家庭详细地址、身份证号。

家庭详细地址仅能在家长创建具体预约订单时填写，并按订单隐私规则保护。家长公开需求中的联系方式授权、预算和详细需求字段，属于“发布家长需求”流程，不在本基础资料页强制填写。

### 6.4 提交与保存规则

1. 必填字段缺失时，页面定位到首个错误字段并提示具体原因。
2. `parentName`、`studySituation`、`teacherRequirement` 不得包含手机号、微信号、二维码链接或门牌地址。
3. 用户提交成功后，创建或更新 `parent_profile`。
4. 如果当前仅拥有家长身份，后端将 `profileStatus` 更新为 `completed`。
5. 如果用户同时拥有老师身份，家长资料保存成功后，当前身份仍为 `parent`，不改变老师资料和审核状态。
6. 提交成功后进入家长版首页；从特定目标流程进入时，优先回到该目标流程。

### 6.5 家长资料接口

**接口：** `POST /api/parent/profile`

**请求头：** `Authorization: Bearer userToken`

**请求参数示例：**

```json
{
  "parentName": "王妈妈",
  "district": "金水区",
  "childGrade": "初二",
  "subjects": ["数学", "英语"],
  "availableTime": ["周六下午", "周日下午"],
  "studySituation": "基础较弱，希望巩固基础题。",
  "teacherRequirement": "希望老师耐心，有初中数学辅导经验。"
}
```

后端必须校验 token、当前身份、字段长度和字典值。成功后返回最新 `userInfo` 和 `parentProfile`。

## 7. 老师资料填写与审核

### 7.1 进入条件

用户满足以下条件时进入老师资料页：

1. 已完成微信登录。
2. `currentRole = teacher`。
3. `profileStatus = pending_profile`，或老师主动编辑资料。
4. 提交前必须完成手机号授权。

### 7.2 页面分组

老师资料页按四组展示：

1. 基础身份信息。
2. 学生认证信息。
3. 授课能力与价格。
4. 个人介绍与适合人群。

页面顶部固定展示说明：

> 提交后将进入平台审核。学生证仅用于后台审核，不会在小程序公开展示。

### 7.3 字段定义

| 字段 | 必填 | 规则 | 对外展示规则 |
| --- | --- | --- | --- |
| 真实姓名 `realName` | 是 | 1 至 20 个字符 | 仅后台审核，不公开 |
| 性别 `gender` | 是 | 男或女 | 公开 |
| 所在学校 `school` | 是 | 1 至 50 个字符 | 公开 |
| 所在专业 `major` | 是 | 1 至 50 个字符 | 公开 |
| 当前年级 `grade` | 是 | 从大学年级字典单选 | 公开 |
| 本人头像 `avatar` | 是 | jpg、jpeg、png；单张不超过 10 MB | 公开 |
| 学生证照片 `studentCardImage` | 是 | jpg、jpeg、png；单张不超过 10 MB | 仅后台审核 |
| 可授课科目 `subjects` | 是 | 至少选择 1 项 | 公开 |
| 可授课年级 `teachGrades` | 是 | 至少选择 1 个价格年级单元 | 公开 |
| 可授课区域 `districts` | 是 | 至少选择 1 项 | 公开 |
| 可授课时间 `availableTime` | 是 | 至少选择 1 项 | 公开 |
| 分年级课时费 `gradePrices` | 是 | 每个已选年级必须填写 1 个合法价格 | 公开 |
| 个人介绍 `intro` | 是 | 1 至 500 字 | 免费展示前 60 字；解锁后完整展示 |
| 教学经历 `teachingExperience` | 否 | 最多 500 字 | 免费展示前 60 字；解锁后完整展示 |
| 适合人群标签 `suitableTags` | 否 | 最多 3 个 | 公开 |
| 微信号 `wechatId` | 否 | 最多 50 个字符 | 仅家长解锁后展示 |
| 可沟通时间 `communicationTime` | 否 | 最多 100 字 | 仅家长解锁后展示 |
| 补充说明 `extraNote` | 否 | 最多 300 字 | 仅家长解锁后展示 |
| 联系方式展示授权 | 是 | 默认不勾选；提交公开资料必须勾选 | 不公开授权状态 |

老师资料不要求上传：学信网截图、奖学金证书、身份证照片、银行卡信息、家庭住址和其他强制能力证明。

### 7.4 分年级课时费规则

老师每选择一个可授课年级单元，必须填写对应价格。后台和前端均按当前启用的价格规则校验。

| 年级单元 | 合法范围 |
| --- | --- |
| 小学 1 至 3 年级 | 50 至 60 元/小时 |
| 初一 | 60 至 80 元/小时 |
| 初二 | 80 至 100 元/小时 |
| 初三 | 100 至 120 元/小时 |
| 高中 | 120 至 150 元/小时 |

示例：老师选择“小学 1 至 3 年级、初一、初二”后，必须分别填写三个价格。老师列表展示最低有效价格，例如“50 元/小时起”；老师详情展示分年级价格明细。

超出当前年级合法范围时，不允许提交，并提示“当前年级课时费需在平台建议范围内填写”。

### 7.5 提交、审核与编辑规则

1. 老师未授权手机号时，点击提交提示“需要授权手机号后才可以提交老师资料”。
2. 老师未勾选联系方式展示授权时，不能提交为公开可展示资料。
3. 表单通过校验后，创建或更新 `teacher`、`teacher_grade_price` 和认证材料记录。
4. 首次提交成功后，`teacherAuditStatus = pending`，`profileStatus = completed`，`currentRole` 保持 `teacher`。
5. 待审核、审核驳回、已封禁老师不能出现在老师列表，不能解锁家长需求，不能接收新预约。
6. 审核通过老师可以进入展示池；是否接收新预约仍受接单状态控制。
7. 审核驳回时，老师端展示驳回原因和“修改资料”入口。
8. 老师修改学校、专业、年级、学生证、授课年级、分年级价格、联系方式授权等关键字段后，审核状态改为 `pending` 或 `rechecking`；第一版可统一使用 `pending`。
9. 审核通过老师在复审期间继续展示旧的已审核公开资料；修改后的关键资料在审核通过前不得替换公开资料。

## 8. 登录与资料页面交互规则

### 8.1 退出与返回

1. 登录页、身份选择页、资料填写页从业务页面进入时，保留返回上一级能力。
2. 用户从首页主动进入登录页，返回时回到首页。
3. 用户在资料填写过程中返回，不自动删除已保存资料。
4. 用户填写未提交时返回，提示“当前填写内容尚未保存，确认离开吗？”。
5. 用户完成资料后，不允许通过返回绕过身份选择或资料完善状态校验进入完整业务页面。

### 8.2 身份切换与新增身份

1. “我的”页面展示当前身份和已拥有身份。
2. 用户已有家长和老师两种身份时，可切换 `currentRole`。
3. 用户只有家长身份时，显示“申请成为老师”入口。
4. 用户只有老师身份时，显示“完善家长资料”入口。
5. 申请新增身份后进入身份选择或对应资料页，不影响已存在身份资料和订单。
6. 切换身份成功后返回首页，首页必须立即按新的 `currentRole` 渲染。

### 8.3 未完成资料的访问拦截

| 用户状态 | 允许访问 | 必须拦截并引导 |
| --- | --- | --- |
| 未登录 | 首页、老师列表、老师公开详情 | 预约、发布需求、解锁、订单详情、老师入驻提交 |
| 已登录待选择身份 | 平台说明、协议、隐私政策 | 首页完整功能、预约、发布需求、解锁、老师提交 |
| 家长待完善资料 | 浏览老师公开信息 | 预约、发布公开需求、解锁老师 |
| 老师待完善资料 | 平台说明、协议、隐私政策 | 提交为公开老师、解锁家长需求、接单 |
| 老师待审核或驳回 | 编辑老师资料、查看审核状态 | 公开展示、解锁家长需求、接收新预约 |

## 10. 隐私与安全要求

1. 用户密码不在本流程中出现，普通用户只使用微信登录。
2. 微信 openid 只在后端存储，不返回普通小程序页面。
3. 手机号以完整值在受控后端存储，小程序普通展示使用脱敏值。
4. 老师学生证照片只允许管理员在审核详情中查看，不允许在老师列表、详情或任何公开接口中返回。
5. 家长资料页不得收集孩子真实姓名、学校、班级和详细家庭地址。
6. 所有需要登录的接口必须验证用户 token。
7. 所有资料提交接口必须由服务端再次校验字段、身份、账号状态和手机号授权状态。
8. 联系方式展示授权必须独立记录；未授权用户不能进入可付费解锁的信息展示池。
9. 资料文本不得绕过联系方式解锁规则；命中疑似手机号、微信号、二维码或精确地址时，服务端必须拦截。
10. 上线前由平台法务或合规负责人复核用户协议、隐私政策、联系方式展示授权文案和数据保存策略。

## 11. 验收标准

### 11.1 微信登录

1. 用户可以在登录页点击微信登录。
2. 用户未同意协议时不能完成登录。
3. 微信新用户登录后 `profileStatus = pending_role`，进入身份选择页。
4. 微信老用户登录后不重复创建用户、不丢失已有资料。
5. 老用户根据 `profileStatus` 和 `currentRole` 进入正确页面。
6. 冻结或封禁用户不能进入完整业务首页。

### 11.2 身份选择

1. 用户可以选择家长身份。
2. 用户可以选择老师身份。
3. 选择家长后进入家长资料填写页。
4. 选择老师后进入老师资料填写页。
5. 用户未选择身份时不能进入完整首页。
6. 双身份用户可在“我的”页面切换已有身份。

### 11.3 手机号授权

1. 用户可以通过微信手机号授权绑定手机号。
2. 授权成功后用户信息显示脱敏手机号和已绑定状态。
3. 家长预约、发布公开需求、解锁老师和提交问题反馈前必须绑定手机号。
4. 老师提交资料、解锁家长需求和修改联系方式前必须绑定手机号。
5. 用户拒绝授权后不能继续对应关键操作。

### 11.4 家长资料

1. 家长可填写称呼、区域、孩子年级、辅导科目和可选补充信息。
2. 家长资料页不收集孩子姓名、学校、班级和详细地址。
3. 家长资料提交成功后 `profileStatus = completed`，进入家长版首页。
4. 家长资料编辑不影响老师资料和老师审核状态。

### 11.5 老师资料

1. 老师必须填写基础资料、学生证、授课能力、分年级课时费和个人介绍。
2. 老师不需要上传学信网截图和奖学金证书。
3. 老师提交前必须已绑定手机号并同意联系方式展示授权。
4. 老师可按多个年级分别设置课时费。
5. 超出价格规则的课时费不能提交。
6. 老师首次提交后审核状态为 `pending`。
7. 待审核、驳回、封禁老师不展示在老师列表，不能解锁家长需求。
8. 审核通过老师才能进入展示池，并可根据接单状态接收预约。

### 11.6 回归要求

1. 不影响现有首页、老师列表、老师详情、预约订单、评价、问题反馈和我的页面。
2. 微信开发者工具可以正常编译。
3. 所有登录、身份、手机号和资料接口失败时展示明确业务提示，不统一显示为网络异常。
4. 小程序页面从登录、身份选择和资料填写页均可按规则返回，不出现无法返回上一级的页面。
